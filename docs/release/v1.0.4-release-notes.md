# MMPay v1.0.4 Release Notes

## Purpose

`v1.0.4` is a patch release that aligns the Huifu adapter with the official
aggregation-payment skill references, scaffolds `qr_code_url` storage and
transport for native QR (`A_NATIVE`) flows, applies a frontend UI audit
(component semantics, layout, navigation), and refreshes CI and frontend
dependencies.

## Backend — Huifu adapter correctness

### Scanpay query payload (bug fix)

- `HuifuPaymentRequestFactory.queryAggregationPayment` previously shared its
  data builder with the refund path, so it sent `req_date` + `req_seq_id` of
  the query call plus `org_req_date` + `org_req_seq_id` of the original
  payment. The official `/v4/trade/payment/scanpay/query` endpoint accepts
  only `huifu_id` + the original payment's `req_date` + `req_seq_id`
  (three-choose-one with `out_ord_id` / `hf_seq_id`) and does not recognise
  any `org_*` prefixed field. Calls would have returned trade-not-found.
- Query and refund now have separate `queryData()` / `refundData()` builders
  with the correct shape each. The query method signature dropped its
  ineffective `requestDate` / `requestSequenceId` parameters and now takes
  only `(originalRequestDate, originalRequestSequenceId)`.

### Lightning SDK request headers

- `HuifuPaymentRequestFactory.headers()` now sets the full Lightning SDK
  baseline per `shared-request-header-policy.md`:
  `sdk_version` and `jpt-sdk_version` (`javaSDK_lightning_1.0.5`), `sys_id`,
  `jpt-sys_id`, `jpt-x-skill-source`, and the conditional
  `jpt-x-skill-huifu_id`. The previous implementation sent only the last
  two, which would have been rejected by Huifu's edge.

## Backend — QR code field scaffolding

- New nullable `qr_code_url` column on `payment_intents`
  (`V134__payment_intent_qr_code_url.sql`, additive and idempotent).
- `ProviderPaymentResponse` SPI now supports a `qrCodeUrl` field alongside
  `redirectUrl`; constructor requires exactly one of them to be set. Static
  factories `withQrCode()` / `withRedirect()` make the caller's intent
  explicit at the SPI boundary.
- `PaymentIntentRow`, `PaymentIntentResponse` (JSON `qr_code_url`),
  `PaymentRepository.markSubmitted()` propagate the field end-to-end so a
  follow-up that wires the live `HuifuPaymentAdapter.createPayment` can
  persist the Huifu `qr_code` return value without further schema or DTO
  changes.

> Note: the live provider client is still unwired; `createPayment` continues
> to throw `ProviderOperationUnavailableException`. The QR plumbing in this
> release is forward-looking scaffolding only.

## Frontend — UI audit

### Payment detail QR panel

- `/payments/:id` now renders an `NQrCode` panel beside the descriptions in
  a 16/8 two-column grid. The QR encodes `qr_code_url` when present and
  falls back to `provider_order_id` or the internal intent ID; the caption
  reads "扫码支付" when a scannable Huifu URL exists.

### Dashboard navigation (regression fix)

- `home/index.vue` now maps backend dashboard navigation keys
  (`channels`, `orders`, `webhook-logs`, `external-readiness`, …) to the
  matching frontend route names (`merchants`, `payments`, `webhook-out`,
  `integrations`, …). Items with no matching route are hidden instead of
  rendered as dead `RouterLink`s. Without this, the `RouterLink + NButton`
  change earlier in this cycle would have emitted 5/8 broken links and
  Vue Router warnings.

### Component semantic fixes

- `merchants/detail`, `channels/detail`: replaced `NStatistic` (numeric
  indicator) with `NDescriptions` for string fields (merchant ID,
  credential ref, fingerprint, provider code).
- `merchants/index`: `credential_ref` column changed from `NTag` wrapper to
  plain text; `credential_fingerprint` column changed from `NTag` to
  `NText` with monospace styling.
- `home/index` empty-table list changed from `NTag` to `NText` (no click
  semantics required); navigation list uses `RouterLink + NButton (text)`.
- `system/index`: native `window.confirm` delete dialog replaced with
  `NPopconfirm`, consistent with the rest of the admin console.

### Layout fixes

- `reconciliation/index` 7-column table wrapped in `overflow-x: auto`
  to prevent horizontal overflow on narrow viewports.
- `home/index` dynamic dashboard tables wrapped in `overflow-x: auto`;
  column count is backend-controlled and unbounded.

- `V134__payment_intent_qr_code_url.sql` adds the nullable
  `qr_code_url VARCHAR(2048)` column. Safe to apply on a live DB
  (`ADD COLUMN IF NOT EXISTS`).

## Upgrade notes

- Backwards-compatible. No API contract removed; all additions are
  optional. No schema changes that require backfill.
- The new SPI factories `ProviderPaymentResponse.withQrCode()` /
  `withRedirect()` are scaffolding for the live Huifu client. Existing
  callers continue to use the all-args constructor; the relaxed
  invariant (`redirectUrl == null && qrCodeUrl == null` rejected)
  preserves the previous "must have a redirect" guarantee in the
  redirect-only constructor path.
