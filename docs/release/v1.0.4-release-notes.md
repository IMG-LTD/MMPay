# MMPay v1.0.4 Release Notes

## Purpose

`v1.0.4` delivers a frontend UI audit pass: layout corrections, component
semantic fixes, and the addition of the native naive-ui QR Code component on
the payment detail page.

## Frontend improvements

### Payment detail — QR Code

- Payment detail page (`/payments/:id`) now renders a `NQrCode` (naive-ui
  built-in) displaying the `provider_order_id` when available, falling back to
  the internal payment intent ID.
- Layout changed from single-column to 16/8 two-column grid: detail
  descriptions on the left, QR code panel on the right.

### Component semantic fixes

- **merchants/detail, channels/detail**: replaced `NStatistic` (numeric
  indicator component) with `NDescriptions` for displaying string fields
  (merchant ID, credential ref, credential fingerprint, provider code). The
  previous use rendered string values in large bold numeric style, which was
  semantically incorrect.
- **merchants/index**: `credential_ref` column changed from `NTag` wrapper to
  plain text. `credential_fingerprint` column changed from `NTag` to `NText`
  with monospace styling. `NTag` is a status/label component and is not
  appropriate for displaying raw string data.
- **merchants/detail**: `credential_ref` column in the channel list table
  changed from `NTag` to plain text.
- **home/index**: navigation items changed from static `NTag` elements to
  `RouterLink + NButton` (text type). `NTag` has no click semantics; navigation
  links require an interactive element.
- **home/index**: empty-table list changed from `NTag` to plain `NText` for
  the same reason.
- **system/index**: delete confirmation changed from `window.confirm` (native
  browser dialog) to `NPopconfirm`, consistent with all other destructive
  confirmations in the codebase.

### Layout fixes

- **reconciliation/index**: 7-column table wrapped in `overflow-x: auto`
  container to prevent horizontal overflow on narrow viewports.
- **home/index**: dynamic dashboard tables wrapped in `overflow-x: auto`
  containers; column count is backend-controlled and unbounded.
