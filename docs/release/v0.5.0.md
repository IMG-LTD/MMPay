# MMPay v0.5.0

`v0.5.0` is the P3 payment lifecycle preview release. It builds on the
Soybean Admin and Pig-aligned merchant/channel baseline from `v0.4.0`.

## Included

- Added upgrade-safe P3 Flyway migrations after `V103` for payment intents,
  provider events, transactions, refunds, reconciliation runs, webhook
  integrations, and delivery logs.
- Added admin APIs for payment intent create/list/detail/cancel, refund
  create/list/detail, reconciliation run list/ack, webhook-out integration
  create, delivery-log list/detail, single redispatch, and guarded bulk
  redispatch.
- Added verified provider callback intake at `/webhook-in/{providerCode}` with
  replay tracking, HMAC signature validation, timestamp window validation, and
  explicit stale-state rejection.
- Added lazy channel credential fingerprint recheck before payment execution, so
  stale credential references fail with a visible conflict instead of silently
  proceeding.
- Added Soybean Admin payment, refund, reconciliation, and webhook-out pages
  using Naive UI components and real admin API calls.
- Extended local validation with the P3 backend contract and repository
  contract so payment lifecycle behavior is covered before release.

## Boundaries

- Live provider calls remain disabled by default through
  `mmpay.provider-live-calls=false`; valid create/refund requests return an
  explicit provider-live-disabled problem until a real provider endpoint is
  enabled and evidenced.
- Huifu MP-8 external evidence is not bundled in this release. Capture the
  redacted sandbox/public-provider evidence with
  `docs/release/e2e-evidence-template.md` after deployment.
- License issuance remains relay-only and vendor-controlled outside this
  repository.
- The immutable GHCR image digest is release evidence only after the remote
  `MMPay Images` workflow completes successfully for tag `v0.5.0`.
