# MMPay v1.0.0-hotfix.1 Release Notes

Status: hotfix release notes prepared

## Purpose

`v1.0.0-hotfix.1` patches the first GA line with a focused set of P0 hardening
items found by post-GA multi-agent audit. The immutable `v1.0.0` tag is
unchanged. This hotfix is built from the post-GA commit on `main` and is
intended to be deployed in place of `v1.0.0` once the GHCR Images workflow
publishes the corresponding signed images.

## Fixed

### Backend

- `payment.acceptCallback` is now `@Transactional`. The `provider_events` insert
  and `payment_intents` state transition can no longer commit independently, so
  a mid-flight failure stops stranding intents at the duplicate-event branch on
  retry.
- `payment.createIntent` audit now records the actual rejection reason. The
  previous code emitted `provider_live_disabled` for every rejection regardless
  of whether live calls were disabled or the live client was unwired.
- `payment.bulkRedispatch` no longer mislabels every repository failure as
  `in_flight`. Only the advisory-lock conflict (`bulk_redispatch_in_flight`)
  audits as `in_flight`; other state-transition errors audit as `rejected` and
  unexpected runtime errors as `internal_error`.
- `LicenseRelay.dispatch` closes the `HttpResponse<InputStream>` body in a
  try-with-resources block to release HTTP/2 stream windows.

### Frontend admin

- `useAuthStore.resetStore` no longer calls `authStore.$reset()`. Pinia setup
  stores do not synthesise `$reset`, and the prior code recursed into
  `useAuthStore()` inside its own setup, which threw at runtime on every
  session-expired or login-failure path. State is now reset in-place.
- `refreshTokenOnce` validates that the refresh response carries both `token`
  and `refreshToken` before persisting. A backend payload with only `token`
  used to clobber the stored refresh token to `undefined` and force a permanent
  logout cascade on the next 401.
- `refreshTokenOnce` clears the in-flight promise synchronously in `finally`
  instead of via `setTimeout(0)`. Removes the race where a second 401 saw a
  resolved promise and forced an unwanted logout in multi-tab admin sessions.
- Webhook upstream save now guards against double-submit. The `保存 upstream`
  button shows loading state and rejects re-entry, so a double-click no longer
  creates duplicate integrations through fresh `Idempotency-Key` headers.

## Compatibility

- Database schema: unchanged from `v1.0.0`.
- Helm chart: unchanged. `deploy/helm/mmpay/values.yaml` continues to default
  `image.tag` to `v1.0.0`. Operators wanting the hotfix should override
  `--set image.tag=v1.0.0-hotfix.1` against the existing chart.
- Docker compose: unchanged from `v1.0.0`.
- Audit chain: unchanged. Pre-existing audit segments verify with
  `mmpay-audit-verifier` exactly as before. New audit fields use existing keys.

## Verification

- `bash scripts/validate-local.sh` passes against the hotfix commit.
- The `v1.0.0` tag remains immutable. The v1 tag ruleset
  (`governance/github-rulesets/v1-tags.json`) continues to enforce
  `deletion`, `non_fast_forward`, and `creation` rules across `refs/tags/v1.*`.
