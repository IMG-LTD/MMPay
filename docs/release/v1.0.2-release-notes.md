# MMPay v1.0.2 Release Notes

Status: patch release notes prepared

## Purpose

`v1.0.2` fixes several frontend issues discovered after the v1.0.1 deployment
to `pay.mmmail.com.cn`.

## Fixed

- **Setup redirect**: On initial deploy (no admin account exists), the SPA now
  probes `HEAD /setup` on the first unauthenticated navigation and redirects to
  the server-rendered setup page when it returns 200.

- **Undefined IDs in API requests**: Detail pages (`/merchants/:id`,
  `/payments/:id`, `/refunds/:id`, etc.) were generating requests like
  `/api/admin/merchants/undefined` because the route paths in `routes.ts` used
  static paths (`/merchants/detail`) instead of dynamic params. All detail
  routes now use `:id` params with `props: true` auto-injection.

- **Sub-menu labels showing route keys**: Sub-menu items displayed raw route
  keys (e.g., `route.merchants_channel-new`) instead of translated labels.
  Root cause: the `elegant-router.d.ts` type file used the old SoybeanAdmin
  nested underscore naming convention. All route names are now flat hyphenated
  keys matching the i18n translation keys.

- **Payment translations**: "支付意图详情" → "支付详情", "支付意图" → "支付",
  "暂无支付意图" → "暂无支付记录", "创建支付意图" → "创建支付".

- **Login page cleanup**: Removed unused modules (code-login, register,
  reset-pwd, bind-wechat), hardcoded demo accounts (Super/Admin/User), and
  the "Remember me" / "Forgot password" / "Other login methods" UI elements.
  The login page now shows only the password login form, branded as MMPay Admin.

- **Brand scan**: Removed `soybeanjs` URL references from manually maintained
  router files to pass the brand-neutrality governance scan.
