# MMPay v1.0.3 Release Notes

## Purpose

`v1.0.3` delivers the system user management module, role-based route access
control, and a set of security and transactional correctness fixes identified
during a full business-logic audit.

## New features

### User management (admin only)

- New `/system` page in the admin console: list all human users, create users,
  edit role and password, delete users.
- Role-coloured tags: admin (red), ops (yellow), finance (green), auditor (blue).
- Self-delete and self-role-change are blocked at both the API and UI layers.
- New backend endpoints under `/api/admin/users` (ADMIN role required):
  `GET /`, `POST /`, `PATCH /{username}`, `DELETE /{username}`.
- All user mutations are audit-logged via `AuditWriter`.

### Role-based route access control

- All admin console routes now declare `meta.roles` so non-privileged users
  cannot navigate to pages they are not authorised to see.
- Route guard enforces role checks on every navigation; ADMIN bypasses all
  checks via `isStaticSuper`.
- Role mapping: `system`, `integrations` → ADMIN only; `merchants`, `webhooks`
  → ADMIN + OPS; `payments`, `refunds`, `reconciliation` → ADMIN + OPS + FINANCE.

## Security fixes

- **Dashboard endpoint**: `GET /api/admin/dashboard` now requires
  `@PreAuthorize("hasAnyRole('ADMIN','OPS','FINANCE','AUDITOR')")`.
  Previously any authenticated principal (including service accounts) could
  access it.

- **Setup race condition**: `SetupController` now consumes the one-time setup
  token (`tokenService.verify`) *before* creating the bootstrap admin account.
  The previous order allowed two concurrent requests to both pass the token
  check and both attempt admin creation.

- **Self role-change prevention**: `UserAdminService.patchUser` now rejects
  requests where the requesting user attempts to change their own role
  (`cannot_change_own_role`), preventing accidental self-demotion.

## Correctness fixes

- **`MerchantAdminService`**: `createMerchant`, `patchMerchant`,
  `archiveMerchant`, `createChannel`, `patchChannel`, `archiveChannel` are now
  `@Transactional`. Previously a partial failure (e.g. audit write after DB
  write) could leave the database in an inconsistent state.

- **`PaymentService.cancelPaymentIntent`**: now `@Transactional` — the DB
  update and audit emit are now atomic.

- **`MerchantAdminService`**: removed `final` modifier so Spring CGLIB can
  generate the transactional proxy.

## Database migrations

- `V102__sys_user_created_at.sql`: adds `created_at TIMESTAMPTZ DEFAULT NOW()`
  to `sys_user`. Safe to apply on a live database (`ADD COLUMN IF NOT EXISTS`).

## Repository governance

- Added `CLAUDE.md` with branch naming, commit format, version/release rules,
  and AI collaboration guidelines.
